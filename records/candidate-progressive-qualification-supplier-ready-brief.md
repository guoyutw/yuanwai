# Candidate: Progressive Qualification / Supplier-Ready Brief

**Status: candidate direction to validate; not canonical product or business-model truth.**

## Candidate flow

Natural-language inquiry → extract what is already known → detect gaps → ask conditional follow-up questions → produce a supplier-ready brief → vendor pricing/proposal.

This applies whether the first contact is short or already detailed. The system should not re-ask known information and should not force a complete RFQ at the first turn.

## Current field-role hypothesis

- service type: routing
- location/area: qualification and serviceability
- date: availability gate
- headcount/quantity: pricing context

Potentially conditional or later:

- explicit budget
- exact time
- menu details
- dietary requirements
- equipment/setup
- invoice/tax ID
- deposit/payment
- access, parking, or vehicle information

These are roles for experiment design, not a fixed form schema or universal required-field list.

## Boundary

This candidate is not:

- a marketplace decision;
- an automated-quote commitment;
- a vendor SaaS architecture;
- a complete RFQ form;
- an autonomous negotiation system.

A minimal Yuanwai LINE customer entry is now part of the current execution path because the owner selected AI-first customer interaction. This does not make a full LINE automation / recording platform a requirement; only the smallest loop needed for the live qualification experiment is current.

## Next validation

Run an AI-first qualification experiment on at least five real new inquiries, with the customer interacting with Yuanwai AI from the first message and a hidden human gate only when a supplier business commitment is required. For each case, preserve only public-safe structured evidence: initial fields present, AI follow-up questions, redundant-question check, turns/messages to supplier-ready, vendor re-ask check, hidden-human intervention count/reason, unsupported-commitment check, first-price status, newly discovered major gap, and observable friction or abandonment.

After the experiment, compare the live evidence with the historical baseline and decide **KEEP**, **REVISE**, or **DROP** this candidate.
